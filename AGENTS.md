## Accessibility & HTML5 Semantics

When creating or modifying HTML markup across pages:

- **Accessible Names**: Interactive elements must have an accessible name. Prefer meaningful visible text. Use `aria-label` when visible content does not provide a sufficient accessible name, such as icon-only controls or ambiguous repeated buttons. Do not add redundant `aria-label` attributes to elements that already have clear visible text.
- **Dates & Date Ranges**: Use standard HTML5 `<time datetime="...">` tags for all dates, years, and date ranges.
- **Decorative Elements**: Apply `aria-hidden="true"` to non-semantic visual decor, decorative SVGs (including layout crosshairs, corner markers, card dot patterns, decorative icons), and visual cursors so assistive technologies ignore them.
- **Color Contrast**: Ensure all text, headings, badges, and interactive states maintain WCAG AA compliant contrast ratios (at least 4.5:1 ratio against backgrounds). Prefer `text-slate-500` or darker over `text-slate-400` for light-mode text/headings, and use `-700` text shades (e.g. `bg-red-50 text-red-700`) for light-mode badges.
- **Semantic Structure**: Prefer standard HTML5 structural elements (`<time>`, `<header>`, `<footer>`, `<main>`, `<nav>`, `<article>`, `<section>`) and maintain a logical, sequentially descending heading hierarchy (`<h1>` -> `<h2>` -> `<h3>` without skipping levels).
- **Keyboard Navigation**: Ensure custom interactive controls (e.g. drawers, copy buttons, theme toggles) are operable via keyboard and support standard key events like Escape. Do not use ARIA to replace good semantic HTML.

## Performance & Core Web Vitals

When maintaining or building interactive components and assets:

- **Minimal Main-Thread Overhead**: Avoid unnecessary JavaScript and long execution tasks. Keep client-side scripts lean.
- **Animation Loops**: Use `requestAnimationFrame` for dynamic animation loops when appropriate, and avoid unnecessary polling loops.
- **Visibility Checks**: Pause animation loops or expensive work when content is not visible where practical (e.g. using `IntersectionObserver`).
- **Font Delivery**: Load Google Fonts using `<link rel="stylesheet">` with `display=swap` and preconnect links in `<head>`. Avoid `@import` rules in CSS files to prevent blocking network waterfalls.
- **Layout Shift (CLS)**: Images (`<img>`) must maintain explicit `width` and `height` attributes alongside matching CSS aspect ratios (`aspect-square` / `aspect-ratio: 1 / 1`) to reserve intrinsic space and prevent layout shifts.
- **Measured Optimizations**: Optimize based on actual behavior rather than assumptions. Avoid unnecessarily large DOM structures and preserve fast initial rendering.

## Tips Platform & Architecture

The developer tips platform (`tips.html` and `tips/<slug>.html`) is statically generated from Markdown files in the `content/tips/` submodule.

### Build Scripts
- `scripts/build-tips.mjs`: Main orchestrator that parses markdown files, normalizes metadata, generates `tips.html`, creates individual `tips/<slug>.html` pages, writes `public/tips-search-index.json`, regenerates `public/sitemap.xml`, and outputs `public/tips/feed.xml`.
- `scripts/tips/tips-helpers.mjs`: Centralized date normalization (`normalizeDateStr`, `getTipEffectiveDate`), date formatting (`formatDate`, `toRfc822Date`), XML escaping (`wrapCdata`), string sanitization (`slugify`, `extractSummary`, `escapeHtml`, `escapeJsonStr`), `marked` code renderer with `highlight.js`, CSS grid styles, and icon sprite definitions.
- `scripts/tips/tips-hub.mjs`: Renders the hub archive page `tips.html` with category filters, subcategory pills, search controls, and drawer navigation.
- `scripts/tips/tips-single.mjs`: Renders individual tip pages in `tips/<slug>.html` with syntax-highlighted code blocks, metadata headers, author bylines, related tips, and structured JSON-LD schemas.
- `scripts/tips/tips-rss.mjs`: Compiles the RSS 2.0 XML feed at `public/tips/feed.xml`.
- `scripts/tips/tips-sitemap.mjs`: Updates `public/sitemap.xml` with static site routes and individual tip URLs.

### Date Normalization Rules
The codebase supports several field aliases for dates. Never access raw date properties directly when determining effective dates. Always use the centralized helpers in `scripts/tips/tips-helpers.mjs`:

- `createdAt = normalizeDateStr(data.created_at || data.date)`
- `updatedAt = normalizeDateStr(data.updated_at || data.updated || data.last_updated)`
- `effectiveDate = getTipEffectiveDate({ created_at, updated_at })` (or `updatedAt ?? createdAt`)

## Tips Date Semantics

Distinguish clearly between creation dates, modification dates, and effective sorting dates:

- **`datePublished`**: Original `createdAt` value. Used for JSON-LD `TechArticle` (`datePublished`) and OpenGraph (`article:published_time`).
- **`dateModified`**: Normalized `updatedAt` value. Included in JSON-LD `TechArticle` (`dateModified`) and OpenGraph (`article:modified_time`) only when `updatedAt` exists.
- **`effectiveDate`**: `updatedAt ?? createdAt`. Used for:
  - Archive listing sort order (descending)
  - RSS feed `<pubDate>`
  - Sitemap `<lastmod>`
  - Visual display on cards and single tip pages (displays `Updated <date>` when `updatedAt` is present; displays `<date>` without prefix when unchanged)

Rules:
- Do not replace original publication dates with updated dates in structured data.
- Do not overwrite `created_at`.
- Do not invent `updated_at` values.

## Structured Data (JSON-LD)

Whenever pages are created or modified:

- **Home (`index.html`)**: Canonical `ProfilePage` and `WebSite`. Its `mainEntity` embeds the complete `Person` entity inline.
- **Collection Pages (`projects.html`, `opensource.html`, `talks.html`, `tips.html`)**: Use `@type: "CollectionPage"`.
- **Services (`services.html`)**: Uses `WebPage` with distinct `OfferCatalog` entries under `mainEntity` (`services#catalog` for Laravel Engineering Services, `services#sponsorships` for Sponsorships & Partnerships, and `services#consultations` for 1:1 Technical Consultations).
- **Tip Pages (`tips/<slug>.html`)**: Include `@type: "TechArticle"` and `@type: "BreadcrumbList"`.

### JSON-LD String Escaping Rule
When injecting dynamic values into inline `<script type="application/ld+json">` blocks:
- Always use `JSON.stringify()` or `escapeJsonStr()` (from `scripts/tips/tips-helpers.mjs`).
- Never use `escapeHtml()` for JSON-LD values. HTML escaping converts characters into entities (`&quot;`, `&amp;`) which corrupts JSON-LD, and fails to escape backslashes, causing syntax errors.
